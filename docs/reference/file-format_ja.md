# ファイルの形式

> 英語版が正本（`file-format.md`）。この文書はその日本語版。

fnaze の説明のファイルの置き場所・名前・中身の書き方。

## 置き場所

```
.fnaze/
	changes/
		<日時>_<UUID>.txt                ← en
		<日時>_<UUID>_<言語の名前>.txt   ← en 以外
```

- `.fnaze/` は `fnaze init` が作る。fnaze は、今のディレクトリ（`-C` を渡したときはそのディレクトリ）から上へたどって、最初に見つけた `.fnaze/` を使う。`.fnaze/` はプロジェクトに1つだけで、入れ子にしない（すでにある `.fnaze/` の下では、`fnaze init` が失敗する）。`.fnaze/` のあるディレクトリを、この文書では「ルート」と呼ぶ
- **説明のファイル1つが、変更のまとまり1つ**を説明する。それがどの変更か（コミット1つなど）は、使う人が決める

## ファイル名

```
<日時>_<UUID>[_<言語の名前>].txt
```

| 部分 | 形 | 内容 |
|---|---|---|
| 日時 | `YYYYMMDDTHHMMSSZ`（16文字） | `fnaze new` が作った時刻（UTC） |
| UUID | `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`（36文字、小文字の16進） | `fnaze new` が作るたびに作るランダムな UUID |
| 言語の名前 | 1文字以上。ASCII の英字（大文字・小文字）と数字 | 任意の文字列。`en` のときは、`_` ごと省く |

- **名前の順（バイトの順）に並べると、作った順になる。** 日時が同じなら UUID の順。そのため、同じ秒に作った2つの組は、作った順に並ぶとは限らない
- **同じ `<日時>_<UUID>` を持つファイルの組**が、1つのまとまりの言語ごとの説明（この文書では「組」と呼ぶ）
- **言語の名前の読み方**：先頭の日時と UUID は長さが決まっているので、そのあとの `_` から `.txt` の前までを言語の名前として読む
- **言語の名前は、fnaze にとってただの文字列。** `ja` が日本語であることを fnaze は知らない。特別なのは `en` だけで、接尾辞を付けない
- 大文字と小文字は別の言語（`ja` と `JA`）。特別なのは小文字の `en` だけ。大文字と小文字だけが違う2つの言語は、1つの組に入れられない。大文字と小文字を区別しないファイルシステム（macOS・Windows）では、ファイル名が同じファイルになるため
- `_en.txt` という名前は使えない（`en` は接尾辞なしで書く）
- この形に合わない名前のファイルは、`.fnaze/changes/` にあっても読まない（`status` で知らせる）

例：

```
.fnaze/changes/
	20261107T003426Z_8980a325-8b57-49b0-8e0a-ed0aaf9eeda7.txt
	20261107T003426Z_8980a325-8b57-49b0-8e0a-ed0aaf9eeda7_ja.txt
	20261107T021530Z_2c4cc818-64d6-45e8-9f3a-5471dba04be7.txt
	20261107T021530Z_2c4cc818-64d6-45e8-9f3a-5471dba04be7_ja.txt
```

## 中身

UTF-8 のテキスト。改行は LF。1行目に題、2行目から1行に1つずつ、エントリまたは detail を書く。

- **読むとき**：行末の空白とタブは取り除く。CR も取り除く（CRLF の改行も読める）。空行は無視する。最後の行の改行は、あっても無くてもよい。BOM は形の誤り
- **書くとき**（`new`・`title`・`set`・`rm`）：改行は LF で、最後の行にも付ける。空行は書かない。行末に空白を書かない（空の題の `# ` だけは除く）。手で揃えた桁や空行は、fnaze が書くと消える

```
# 認証のセッションの期限を、固定から延長に変えた
src/
	auth/	期限を固定から延長に変えた
		session.go	アクセスのたびに期限を延ばす
		*_test.go	延長のテストを足す
config/auth.yaml	session.ttl の既定を 30m にした
	| 短すぎてセッションが切れる報告があった
docs/old.md	消した。内容は docs/auth.md に移した
```

（インデントと、パスと desc の区切りは、どちらもタブ）

### 題（1行目）

- `# ` で始め、そのあとに、このまとまりが何の変更かを1行で書く
- そのファイルの言語で書く
- `#` だけ、または `# ` だけの行は、空の題
- 1行目が `#` で始まらないとき、`#` のすぐ後が空白でないとき（`#題`）は、形の誤り

### エントリ

```
<インデント><パス>[<タブ><desc>]
```

- **インデント**はタブだけ。1段につきタブ1つ。行のインデントは、直前のエントリより2段以上深くできない
- **パス**は `/` 区切り。ディレクトリは末尾に `/` を付ける
  - 1段目のエントリのパスは、ルートからのパス
  - インデントしたエントリのパスは、すぐ上の浅いディレクトリのエントリのパスにつなげて読む（例の `session.go` は `src/auth/session.go`）
  - パスの中に `/` を含めてよい。途中のディレクトリの行を書かずに済む（例の `config/auth.yaml`）
  - インデントの下に子を持てるのは、ディレクトリのエントリだけ
  - `.`・`..`・空の部分（`a//b`）、先頭の `/` は使えない
- **desc** は1行。長さの上限は無い
  - 行の最初のタブより後ろすべてが desc で、前後の空白とタブは取り除く。手で桁を揃えるタブは書いてよく、desc の中のタブは残る
  - そのため、パスにはタブを含められない
- **desc の無いエントリ**：
  - 子のあるディレクトリのエントリなら、深い場所に書くための骨組み（例の `src/`）
  - 子の無いエントリなら、**空の desc**（書き忘れ）
- **同じパスのエントリ**を、1つのファイルに2つ書けない
- **パスが今あるかどうかは見ない。** 消したファイル・名前を変える前のファイルも書ける（例の `docs/old.md`）

### パターン

- パスの最後の部分に `*` を書ける。`*` は、`/` 以外の任意の文字の並び（空も含む）に当たる
- パターンが当たるのは、書いたディレクトリの直下だけ（例の `*_test.go` は `src/auth/` の直下に当たり、`src/auth/x/` の中には当たらない）
- ディレクトリのパターンも書ける（`gen-*/`）

### ディレクトリの desc

ディレクトリの desc は、その下の変更をまとめて説明する。大きな名前の変更や機械的な書き換えのとき、ファイルを1つずつ書かずに済む。

あるパスの説明を引くときは、近いものを使う：

1. そのパスのエントリ
2. そのパスに当たるパターン
3. いちばん近い上のディレクトリのエントリ（desc のあるもの）

### detail

```
<インデント>| <detail>
```

- detail の行は、`|` だけの行か、`| ` で始まる行。`|` だけの行は、補足の中の空の行。`|題` のような行は detail ではない（エントリとして読む）。`|` だけ、または `| ` で始まるパスは書けない
- 直前のエントリの補足（理由やいきさつなど）。インデントは、そのエントリより1段深くする
- 1つのエントリに、いくつも続けて書ける。書いた順に1つの補足として読む
- 長さの上限は無い

### 言語ごとのファイル

- 同じ組のファイルは、**同じパスの行を同じ順で持つ**。違うのは、題・desc・detail の言葉だけ
- 組にどの言語があるべきかは、fnaze は決めない（組ごとに、`fnaze new` が作った言語）
