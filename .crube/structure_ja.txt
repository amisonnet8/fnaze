.claude/	リポジトリで共有する Claude Code の設定
	hooks/	Claude Code が道具の前後に動かすフック
		build.sh	Edit・Write で .go・go.mod・go.sum を変えたあとに qsoku build を動かす
		crube-untracked.sh	Write でファイルを作ったあと、説明の無いパスを言語ごとに Claude に知らせる
	rules/	このリポジトリで作業するときのルール（日本語）。いつ読むかは CLAUDE.md にある
		crube-usage.md	crube の使い方：MCP と CLI、場所の探し方、両方の言語の説明の保ち方
		datetime.md	日時の扱い：UTC で持ち、表示だけ利用者のタイムゾーンに直す
		directory-structure.md	ファイルの置き場所と、リポジトリの構成
		distribution.md	配布の方法：goreleaser での配布物の作り方と、リリースの流れ
		documentation.md	文書の書き方：例の値は道具で求める、docs/design/ に書く経緯の線引き
		mtqg-usage.md	mtqg でメモ・todo・質問・不具合・決まり事を記録する方法
		naming.md	命名規則：製品名、用語（英語・JSON での表記つき）、コマンドと MCP の道具の名前
		qsoku-usage.md	ビルド・テスト・lint の qsoku の名前と呼び方
		testing.md	テスト方針と、サンドボックス・OS ごとの CI の落とし穴
		working-with-human.md	人間への頼み方：小さなつまずき、確認、見え方の了承
		fnaze-usage.md	このリポジトリでの fnaze の使い方：コミットごとに fnaze で説明を書く手順、pre-commit、落とし穴
	settings.json	Claude Code の許可・サンドボックス・フック（人間が管理する）
	skills/	Claude Code のスキル
		mutation-check/	スキル：実装をわざと壊して、テストが気づくか確かめる
			SKILL.md	スキルの手順
			spec.txt	プロジェクトの仕様の約束を1つずつ壊す変異の一覧（仕様の言葉で書く。最初は空）
			mutants/	変異を入れてテストを回す道具（独立した Go モジュール）
				go.mod	モジュールの定義（このプロジェクトとは別）
				main.go	構文の変異、または一覧の変異を1つずつ入れ、ファイルを元に戻す
				main_test.go	道具のテスト
.devcontainer/	開発用のコンテナ
	devcontainer-lock.json	コンテナを作ったときの feature の版
	devcontainer.json	コンテナの定義と VS Code の設定
	postCreate.sh	コンテナを作ったあとに道具（qsoku・mtqg・crube・goreleaser・golangci-lint・Trivy）を入れ、挙げたシェル（初めは bash だけ）を配線する
.github/	GitHub の設定
	workflows/	GitHub Actions のワークフロー
		ci.yml	CI：Linux・macOS・Windows での qsoku check、race、ShellCheck、Trivy
		release.yml	タグで動くリリース。ci.yml を通してから、goreleaser の配布物を Release に添付して公開する
.mtqg/	mtqg の作業記録：メモ・todo・質問・不具合・用語・決まり事
	.gitattributes	journal.jsonl を merge=union でマージする
	.gitignore	.local/ を git に入れない
	SCHEMA.md	journal.jsonl のデータ形式
	journal.jsonl	記録そのもの。1件1行の JSON（mtqg からだけ書く）
	version	mtqg のデータ形式の版
docs/	プロジェクトの文書
	design/	設計（英語が正本で、*_ja.md が日本語版）
		overview_ja.md	overview.md の日本語版
		overview.md	fnaze の目的、しないこと、設計の決まりとその理由（英語の正本）
	examples/	使う人のための例
		changes/	説明のファイルの組を2つ、en と ja で。.fnaze/changes/ に置かれる形のまま
			*.txt	説明のファイル（en は接尾辞なし、ほかは _<言語の名前>）
		pre-commit	コミット1つにつき説明を1つ書く使い方のための、git の pre-commit フックの例
		README.md	例の一覧（英語）
		README_ja.md	README.md の日本語版
	reference/	仕様（英語が正本で、*_ja.md は日本語版）
		commands.md	コマンド（英語）
		commands_ja.md	commands.md の日本語版
		file-format.md	説明のファイルの置き場所・名前・書き方（英語）
		file-format_ja.md	file-format.md の日本語版
	assets/	README の画像
		header.svg	README の先頭のヘッダーの画像。手で描いたもの
		demo.svg	ターミナルで動く fnaze。README.md の先頭に置く
			| TestDemoSVG（e2e/demo_test.go）が fnaze の出力から作る。作り直すときは qsoku demo。
		demo_ja.svg	FNAZE_LANG=ja で動く fnaze。README_ja.md の先頭に置く
			| demo.svg と一緒に TestDemoSVG が作る。作り直すときは qsoku demo。
internal/	このモジュールの中だけで使うパッケージ
	format/	説明のファイル1つを読み書きし、そのファイルだけで分かる問題を見つける
		| 題・エントリ・detail。形の誤り・空の題・空の desc。読み方と書き方は crube の structure.txt に合わせた
		format.go	読む（Parse）、決まった形で書く、fnaze new の骨組み、言語ごとのずれを比べるパスの行
		format_test.go	読み書きのテスト。docs の例と、仕様の場合分けで確かめる
		edit.go	ファイルの木を書き換える：CheckPath・Find・Set（fnaze set）・Remove（fnaze rm）・Count
		edit_test.go	set がエントリを足す位置、detail の行、rm が消すもののテスト
	lang/	言語の名前を検査し、FNAZE_LANG を読む
		| 言語は ASCII の英数字。1つの組の言語は、重なったり、大文字と小文字だけ違ったりしてはいけない
		lang.go	Check・CheckGroup・FromEnv と、1つの言語を取るコマンドの言語を決める One
		lang_test.go	検査と、言語の決め方のテスト
	name/	説明のファイルの名前 <日時>_<UUID>[_<言語>].txt を読み、作る
		name.go	Parse・File・IsGroup・Datetime と NewGroup（時計と乱数は呼ぶ側が渡す）
		name_test.go	名前のテスト。期待する UUID は Python の uuid で求めた
	project/	ルート（.fnaze/ のあるディレクトリ）を探し、.fnaze/ を作る（fnaze init）
		project.go	Find・ChangesDir・Init
		project_test.go	ルートの探し方と init のテスト。一時ディレクトリで確かめる
	core/	fnaze の判定のすべて。CLI と MCP はこれを包む
		| new・set・rm・status・show・log、組と言語の決め方、--json と MCP の JSON にもなる結果
		core.go	Open と Init、.fnaze/changes/ を組に分けて読むこと、組を名前の先頭の一部から見つけること
		commands.go	各コマンドと、その結果（JSON の型）
		core_test.go	一時ディレクトリのルートで、docs の例と、固定した時計と乱数を使ってコマンドを確かめる
		json.go	JSON：結果の JSON。--json と MCP の道具が同じものを使う
	cli/	fnaze のコマンドライン。internal/core の薄い包み
		| 引数を core の呼び出しに、結果をテキストか JSON にする。終了コード 0・1・2
		args.go	1つのコマンドのオプションと引数を読む
		cli.go	Run：コマンド、使い方、--version、-C、--json、終了コード
		text.go	new・status・show・log のテキストの出力。表示幅でそろえる
		cli_test.go	一時的なルートでコマンドラインを動かすテスト
		text_test.go	テキストの出力、表示幅、組の短い名前のテスト
		mcp_test.go	MCP の道具が、コマンドと同じ JSON とエラーを返すことのテスト
		complete.go	fnaze completion と、スクリプトが呼ぶ隠しコマンド fnaze __complete
			| コマンド、オプション、題を添えた組、言語、1段ずつのエントリのパス。core の Log と Show から求める
		complete_test.go	__complete の候補とスクリプトのテスト
		completions/	補完のスクリプト。fnaze に埋め込む
			| 決まった文字列。TAB のたびに fnaze __complete に聞くので、入っている fnaze と食い違わない
			fnaze.bash	bash の補完
			fnaze.zsh	zsh の補完
			fnaze.fish	fish の補完
			fnaze.ps1	PowerShell の補完
	mcpserver/	fnaze mcp の MCP サーバー。internal/core の薄い包み
		| 読む道具 show・status・log と、--allow-write のときの書く道具 new_group・set_description・remove_description。どれも core.JSON（--json と同じ JSON）を返す
		server.go	道具とその引数、標準入出力で動かす Run
		server_test.go	メモリの中の接続で道具を呼ぶテスト
.gitattributes	改行（すべて LF）
.gitignore	git に入れないもの。ルート直下のドットで始まる名前は許可リスト方式
.golangci.yaml	golangci-lint の設定
.mcp.json	Claude Code に mtqg と、crube（英語・日本語）と、fnaze 自身（1つ）の MCP サーバーをつなぐ設定
CLAUDE.md	このリポジトリでの Claude Code のルールと、読むべきルールファイルの案内
LICENSE	MIT ライセンス
README.md	fnaze とは何か、入れ方と使い方、文書の場所（英語の正本。日本語版は README_ja.md）
go.mod	Go モジュールと依存
qsokufile	ビルド・テスト・lint の名前つきコマンド（qsoku）
trivy.yaml	Trivy の設定：何を脆弱性・ライセンスの失敗とみなすか
.goreleaser.yaml	配布物の作り方（goreleaser）
	| タグで .github/workflows/release.yml が、手元では qsoku snapshot が使う。.claude/rules/distribution.md を参照。
tools/	プロジェクトを作るための道具（実行ファイルには組み込まれない）
	licenses/	配布物に入れる依存のライセンス文を集める
		| go run ./tools/licenses <dir> <main パッケージ>。goreleaser がビルドの前に動かす。ライセンスのファイルが無いモジュールがあれば失敗する。
		main.go	実行ファイルに組み込まれるモジュールを go list -deps で求め、ライセンス文を写す
		main_test.go	ライセンス文を集める処理のテスト。TestRun は fnaze に組み込まれるもののライセンスの一覧を確かめる
cmd/	実行ファイル
	fnaze/	fnaze のコマンド
		main.go	main：引数と版を internal/cli に渡す
go.sum	依存のチェックサム
e2e/	端から端までのテスト：ビルドした fnaze、その MCP サーバー、本物のシェルでの補完のスクリプト、docs/ の例
	| go test ./...（qsoku check）で動く。TestMain が fnaze を1回ビルドする。入っていないシェルや git は飛ばす
	helpers_test.go	fnaze を1回ビルドし（TestMain）、プログラムとして動かす。時計と乱数を固めて、このプロセスの中で動かすこともできる
	commands_test.go	ビルドした fnaze の全コマンドを、使う人と同じように動かす：サブディレクトリ、FNAZE_LANG、-C、--json、エラー、ヘルプ
	docs_test.go	docs/reference/・docs/examples/・README のコードブロックをすべて、fnaze の実際の出力と突き合わせ、pre-commit の例を git で動かす
	mcp_test.go	ビルドした fnaze mcp を標準入出力でつなぐ：出す道具と、--json と同じ JSON・エラー
	completion_test.go	補完のスクリプトを、本物の bash・zsh・fish・PowerShell で、ビルドした fnaze を PATH に置いて動かす
	demo_test.go	fnaze の出力から docs/assets/demo.svg と demo_ja.svg を描き、今の出力と合っているかを確かめる
.fnaze/	fnaze 自身のデータ：このリポジトリのコミットごとの説明を fnaze で書いたもの（.claude/rules/fnaze-usage.md）
	changes/	説明のファイル。コミット1つにつき組1つ（英語と日本語。初めのころは日本語だけ）
		*.txt	説明のファイル：<日時>_<UUID>_ja.txt。fnaze new で作り、fnaze title・set・rm で書く
.githooks/	このリポジトリの git のフック（core.hooksPath。.devcontainer/postCreate.sh が設定する）
	pre-commit	docs/examples/pre-commit そのまま：説明のファイルを足さないコミットと、いちばん新しい組を fnaze status --require が報告するコミットを止める
README_ja.md	README.md の日本語版
