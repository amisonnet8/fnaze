.claude/	Claude Code settings shared in the repository
	hooks/	Hooks that Claude Code runs around its tools
		build.sh	Runs qsoku build after a .go, go.mod or go.sum file is changed with Edit or Write
		crube-untracked.sh	After Write creates a file, tells Claude which of its paths have no description, per language
	rules/	Rules for working in this repository (Japanese); CLAUDE.md says when to read each
		crube-usage.md	Using crube: MCP and the CLI, finding places, keeping descriptions in both languages
		datetime.md	Dates and times: keep UTC, show in the local time zone
		directory-structure.md	Where each file goes, and the layout of the repository
		distribution.md	How the project is released: building the archives with goreleaser, and the release flow
		documentation.md	How to write documents: example values from tools, what history goes in docs/design/
		mtqg-usage.md	How to record memos, todos, questions, bugs and rules with mtqg
		naming.md	Naming rules: the product name, the terms with their English and JSON names, and the names of commands and MCP tools
		qsoku-usage.md	The qsoku names for build, test and lint, and how to call them
		testing.md	Test policy, and pitfalls of the sandbox and of CI on each OS
		working-with-human.md	How to ask people: small blockers, checks, and approval of what users see
		fnaze-usage.md	How this repository uses fnaze: describing each commit with fnaze, the pre-commit hook, and the pitfalls
	settings.json	Permissions, sandbox and hooks of Claude Code (managed by people)
	skills/	Skills of Claude Code
		mutation-check/	Skill: break the code on purpose to see that the tests notice
			SKILL.md	The steps of the skill
			spec.txt	Mutations that break the promises of the project one by one, in the words of the spec (empty at first)
			mutants/	The tool that makes the mutations and runs the tests (a Go module of its own)
				go.mod	Module definition, apart from this project
				main.go	Makes syntactic mutations, or those of a list, one at a time, and puts the files back
				main_test.go	Tests of the tool
.devcontainer/	Development container
	devcontainer-lock.json	Versions of the features the container was built with
	devcontainer.json	Container definition and VS Code settings
	postCreate.sh	Installs the tools (qsoku, mtqg, crube, goreleaser, golangci-lint, Trivy) after the container is made, and wires up the shells it lists (bash by default)
.github/	GitHub settings
	workflows/	GitHub Actions workflows
		ci.yml	CI: qsoku check on Linux, macOS and Windows, the race detector, ShellCheck and Trivy
		release.yml	Release on a tag: runs ci.yml, attaches goreleaser's archives to a Release and publishes it
.mtqg/	Process record kept with mtqg: memos, todos, questions, bugs, glossary and rules
	.gitattributes	Merges journal.jsonl with merge=union
	.gitignore	Keeps .local/ out of git
	SCHEMA.md	Data format of journal.jsonl
	journal.jsonl	The records, one JSON line each (written only through mtqg)
	version	Version of the mtqg data format
docs/	Documents of the project
	design/	The design (English is authoritative, *_ja.md are Japanese translations)
		overview_ja.md	Japanese translation of overview.md
		overview.md	What fnaze is for, what it does not do, and the design rules with their reasons
	examples/	Examples for users
		changes/	Two groups of description files in en and ja, as they would be in .fnaze/changes/
			*.txt	A description file (en without a suffix, others with _<language>)
		pre-commit	An example git pre-commit hook for one description per commit
		README.md	What the examples are
		README_ja.md	Japanese translation of README.md
	reference/	The specification (English is authoritative, *_ja.md are Japanese translations)
		commands.md	The commands
		commands_ja.md	Japanese translation of commands.md
		file-format.md	Where the description files are, their names, and how they are written
		file-format_ja.md	Japanese translation of file-format.md
internal/	Packages used only inside this module
	format/	Reads and writes one description file, and finds the problems of that file alone
		| Title, entries, details; format errors, empty title and empty descs. Reading and writing follow crube's structure.txt
		format.go	Parse, the canonical writer, the skeleton for fnaze new, and the path lines for the language check
		format_test.go	Tests of reading and writing, against the examples in docs/ and the cases of the spec
		edit.go	Changing the tree of a file: CheckPath, Find, Set (fnaze set), Remove (fnaze rm) and Count
		edit_test.go	Tests of where set adds an entry, of the detail lines, and of what rm removes
	lang/	Checks the names of languages, and reads FNAZE_LANG
		| A language is ASCII letters and digits. The languages of one group cannot repeat or differ only in case
		lang.go	Check, CheckGroup, FromEnv, and One (the language of a command that takes one)
		lang_test.go	Tests of the checks and of choosing the language
	name/	Reads and makes the names of description files: <datetime>_<UUID>[_<language>].txt
		name.go	Parse, File, IsGroup, Datetime, and NewGroup (the clock and the randomness are given by the caller)
		name_test.go	Tests of the names; the expected UUIDs are from Python's uuid
	project/	Finds the root (the directory that holds .fnaze/) and makes .fnaze/ (fnaze init)
		project.go	Find, ChangesDir and Init
		project_test.go	Tests of finding the root and of init, in temporary directories
	core/	Every decision of fnaze; the CLI and the MCP server wrap it
		| new, set, rm, status, show and log, choosing the group and the language, and the results that are also the JSON of --json and of MCP
		core.go	Open and Init, reading .fnaze/changes/ into groups, and finding a group from a start of its name
		commands.go	The commands and their results (the JSON types)
		core_test.go	Tests of the commands in temporary roots, with the examples of docs/ and a fixed clock and randomness
		json.go	JSON: the JSON of a result, shared by --json and the MCP tools
	cli/	The fnaze command line; a thin wrapper of internal/core
		| Turns arguments into calls to core and results into text or JSON; exit codes 0, 1 and 2
		args.go	Reading the options and arguments of one command
		cli.go	Run: the commands, usage, --version, -C, --json and exit codes
		text.go	The text output of new, status, show and log, aligned by display width
		cli_test.go	Tests that run the command line on temporary roots
		text_test.go	Tests of the text output, display width and short group names
		mcp_test.go	Tests that the MCP tools return the same JSON and errors as the commands
		complete.go	fnaze completion and the hidden fnaze __complete that the scripts call
			| Commands, options, groups with their titles, languages and entry paths one level at a time, from core's Log and Show
		complete_test.go	Tests of the candidates of __complete and of the scripts
		completions/	The completion scripts, embedded in fnaze
			| Fixed text: at every TAB they ask fnaze __complete, so they never disagree with the fnaze installed
			fnaze.bash	bash completion
			fnaze.zsh	zsh completion
			fnaze.fish	fish completion
			fnaze.ps1	PowerShell completion
	mcpserver/	The MCP server of fnaze mcp; a thin wrapper of internal/core
		| Read tools show, status and log; write tools new_group, set_description and remove_description with --allow-write. Each returns core.JSON, the same JSON as --json
		server.go	The tools, their arguments and Run over stdio
		server_test.go	Tests that call the tools over an in-memory connection
.gitattributes	Line endings (LF everywhere)
.gitignore	Files kept out of git; dot entries in the root are an allowlist
.golangci.yaml	golangci-lint settings
.mcp.json	MCP servers for Claude Code: mtqg, crube in English and Japanese, and fnaze itself (one server)
CLAUDE.md	Rules for Claude Code in this repository, and the rule files to read
LICENSE	MIT license
README.md	What fnaze is, and where its documents are (authoritative; README_ja.md is the Japanese translation)
go.mod	Go module and its dependencies
qsokufile	Named commands for build, test and lint (qsoku)
trivy.yaml	Trivy settings: what counts as a vulnerability or license failure
.goreleaser.yaml	How the release archives are built (goreleaser)
	| Used by .github/workflows/release.yml on a tag, and by qsoku snapshot locally; see .claude/rules/distribution.md.
tools/	Tools for building the project (not built into its command)
	licenses/	Gathers the license texts of the dependencies for the release archives
		| go run ./tools/licenses <dir> <main package>; goreleaser runs it before building. Fails if a module has no license file.
		main.go	Finds the modules linked into the command with go list -deps and copies their licenses
		main_test.go	Tests of the license gathering; TestRun lists the licenses of what fnaze links
cmd/	Executables
	fnaze/	The fnaze command
		main.go	main: passes the arguments and the version to internal/cli
go.sum	Checksums of the dependencies
e2e/	End-to-end tests: the built fnaze, its MCP server, the completion scripts in real shells, and the examples of docs/
	| Runs with go test ./... (qsoku check). TestMain builds fnaze once; a shell or git that is not installed is skipped
	helpers_test.go	Builds fnaze once (TestMain) and runs it as a program, or in this process with a fixed clock and randomness
	commands_test.go	Every command of the built fnaze, as a user runs them: a subdirectory, FNAZE_LANG, -C, --json, errors, help
	docs_test.go	Checks every code block of docs/reference/ and docs/examples/ against what fnaze prints, and runs the pre-commit example in git
	mcp_test.go	The built fnaze mcp over standard input and output: the tools offered, and the same JSON and errors as --json
	completion_test.go	The completion scripts in real bash, zsh, fish and PowerShell, with the built fnaze on the PATH
.fnaze/	fnaze's own data: the description of each commit of this repository, written with fnaze (.claude/rules/fnaze-usage.md)
	changes/	The description files, one group per commit (English and Japanese; earlier ones Japanese only)
		*.txt	A description file: <datetime>_<UUID>_ja.txt, made by fnaze new and written by fnaze title, set and rm
.githooks/	The git hooks of this repository (core.hooksPath, set by .devcontainer/postCreate.sh)
	pre-commit	docs/examples/pre-commit as it is: stops a commit that adds no description file, or whose newest group fnaze status --require reports
README_ja.md	Japanese translation of README.md
